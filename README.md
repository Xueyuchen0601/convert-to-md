# PDF / DOCX 转 Markdown 脚本使用说明

## 一、交付内容

| 文件 | 说明 |
| --- | --- |
| `convert_to_md.py` | 转换脚本本体，Python 3.9+，纯本地运行 |
| `README.md` | 本说明文档 |

脚本只读取源文件并写出 `.md` 文件，**不上传任何文件内容、不修改源文件、不删除任何文件**。

## 二、环境准备

依赖四个第三方库，作用如下（均为本地解析，不调用在线服务）：

| 库 | 用途 |
| --- | --- |
| `pdfplumber` | 解析 PDF 文字坐标、字号、表格线 |
| `mammoth` | 将 DOCX 转换为语义化 HTML |
| `markdownify` | 将 HTML 转换为 Markdown |
| `beautifulsoup4` | 修正 DOCX 表格表头 |

安装命令：

```bash
python -m pip install pdfplumber mammoth markdownify beautifulsoup4
```

国内网络若下载缓慢或中断，建议加镜像：

```bash
python -m pip install -i https://mirrors.aliyun.com/pypi/simple pdfplumber mammoth markdownify beautifulsoup4
```

## 三、快速开始

```bash
# 单个文件，输出到同目录同名 .md
python convert_to_md.py "合同.pdf"

# 整个目录（含子目录），输出到该目录下的 markdown/，并保持原有层级
python convert_to_md.py "D:\案卷材料" -r

# 指定输出目录，清理页眉页脚，并生成可复核的转换报告
python convert_to_md.py "D:\案卷材料" -r -o "D:\markdown" --clean --report

# 混合输入
python convert_to_md.py "判决书.pdf" "起诉状.docx" -o "D:\markdown"
```

## 四、参数说明

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `inputs` | 必填 | 一个或多个文件 / 目录路径 |
| `-o, --output` | 见下方输出规则 | 输出根目录 |
| `-r, --recursive` | 关闭 | 递归处理子目录 |
| `--overwrite` | 关闭 | 允许覆盖已存在的 `.md`；默认跳过，避免误覆盖 |
| `--pdf-mode` | `structured` | `structured`：按字号推断标题、提取表格；`plain`：逐行纯文本，兼容性优先 |
| `--keep-linebreaks` | 关闭 | PDF 段落内保留原始换行（默认合并为自然段） |
| `--clean` | 关闭 | 移除跨页重复页眉页脚、孤立页码，压缩多余空行 |
| `--no-images` | 关闭 | 不导出 DOCX 内嵌图片 |
| `--page-markers` | 关闭 | 插入 `<!-- page N -->` 页码注释，便于回查原件页码 |
| `--report` | 关闭 | 在输出根目录生成 `转换报告.md` |
| `--encoding` | `utf-8` | 输出编码 |

**输出根目录规则（事实）**：指定 `-o` 时一律输出到该目录；未指定时，文件输入输出到文件所在目录，目录输入输出到该目录下的 `markdown/`。批量转换时按相对路径重建子目录。

**退出码（事实）**：`0` = 无转换失败（含全部被跳过的情形）；`1` = 未找到可转换文件；`2` = 至少一个文件转换失败。

## 五、转换规则与判断依据

以下为脚本的**实现选择**，不是对原件版式的精确还原，属于策略判断，需在重要文档中人工复核：

1. **PDF 标题层级**：取「长度 ≥ 12 字符的行」的字号众数作为正文字号基准，再按字号倍差（1.5 / 1.2 / 1.1 倍）推断 `#` / `##` / `###`。同时用「含中文句读且长度 ≥ 12」的规则排除正文段落。依据：法律文书标题通常使用显著大于正文的字号且不含句末标点。该规则是启发式的，存在误判可能。
2. **PDF 段落合并**：同一段落的多行按中文直接拼接、中英之间补空格合并；行距超过中位行距 1.8 倍时另起段落。
3. **PDF 表格**：依据表格线识别，落在表格框内的文字行不再重复输出。
4. **DOCX**：经 mammoth 转 HTML 再转 Markdown，保留标题层级、加粗、斜体、有序/无序列表、表格、超链接；表格首行提升为表头。
5. **DOCX 图片**：默认导出到 `<文件名>_assets/`，Markdown 中使用相对路径引用。

## 六、已知限制与风险提示

| 情形 | 影响 | 建议 |
| --- | --- | --- |
| 扫描件 / 图片型 PDF（无文字层） | 输出为空或近乎为空，脚本会在提示中标注 | 先做 OCR，或改用带 OCR 的工具；本脚本不含 OCR |
| 加密 / 权限受限 PDF | 可能读取失败 | 先解除限制 |
| 无框线表格、合并单元格、跨页表格 | 表格可能错位或漏识别 | 对照原件人工复核；可用 `--pdf-mode plain` 取纯文本再手工整理 |
| 多栏排版、竖排文字、脚注、页边批注 | 阅读顺序可能错乱 | 用 `--page-markers` 辅助回查，人工校对 |
| 标题字号与正文接近 | 标题可能漏判或误判 | 用 `--pdf-mode plain` 降级，或人工补标题 |
| DOCX 文本框、SmartArt、公式、修订痕迹、批注、页眉页脚、下划线/高亮 | 通常不保留 | 需人工核对关键条款 |
| PDF 内嵌图片 | 默认不导出（PDF 内图片多为扫描件或背景，单独提取意义有限） | 如需图片请另行提取 |
| `--clean` 的页眉页脚识别 | 基于「跨页高频重复短行」的统计规则，可能误删重复出现的短条款 | 建议首次使用不加 `--clean`，确认效果后再启用；或配合 `--page-markers` 复核 |

**重要提示**：本脚本输出适合用于检索、摘要、知识库入库等场景，**不应直接作为具有法律效力的定稿文本**。金额、日期、当事人称谓、条款编号等关键信息须逐项与原件核对。

## 八、常见用法建议

- 首次处理一批新材料时，先不加 `--overwrite` 与 `--clean` 跑一次，抽查若干 `.md`；
- 确认版式还原可接受后，再用 `--clean --report` 正式批量转换；
- 需要回溯原文页码时加 `--page-markers`；
- 遇到版式异常的单个文件，单独用 `--pdf-mode plain` 重转，不影响其他文件。
